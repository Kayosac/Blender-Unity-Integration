# Blender Bridge — руководство

Пакет связывает Unity и Blender одной кнопкой в каждую сторону: **Open in Blender** в Unity и **Export to Unity** в Blender. FBX (или .anim) в Assets остаётся источником истины: файл перезаписывается на месте, поэтому GUID, .meta, ссылки префабов, сцен, Addressables и сетевых объектов не рвутся.

## Требования

- Unity 6000.0 и новее.
- Blender 5.2 LTS (работают 5.0 и новее). На macOS Blender 5 требует Apple Silicon и macOS 13+.
- Ставить аддон в Blender не нужно: Unity запускает Blender с аддоном прямо из пакета.

## Установка

1. Package Manager → `+` → **Add package from git URL** → `https://github.com/Kayosac/Blender-Unity-Integration.git`.
2. Unity сама найдёт Blender. Если не нашла: **Preferences ▸ Blender Bridge** → Browse или Detect.
3. По желанию: **Project Settings ▸ Blender Bridge** — папки своего контента, шаблонный материал, срок кэша.

При первом открытии модели появится папка `ArtSource/` рядом с Assets. В ней сразу лежат `.gitignore` (кэш и служебные файлы вне git) и `.gitattributes` (закреплённые .blend через LFS).

## Быстрый старт

1. ПКМ на модели в Project (или на объекте в Hierarchy) → **Blender ▸ Open in Blender**. Либо кнопка **Open in Blender** в шапке инспектора.
2. Правишь в Blender. Панель **Unity** открывается в боковой панели вьюпорта (N).
3. **Export to Unity**. Переключаешься в Unity — она импортирует файл, проверяет, что нетронутое осталось прежним, и пишет итог в консоль и в **Window ▸ Blender Bridge ▸ Reports**.

## Сценарии

| Что делаешь | Откуда | Куда пишется результат |
| --- | --- | --- |
| Правка статичного меша | ПКМ на FBX, на объекте, кнопка в инспекторе | Тот же FBX |
| Правка меша или скелета персонажа | То же | Тот же FBX |
| Новый клип | Открытая модель → **New Clip** в панели | `Модель@Клип.fbx` в `Animations/` рядом с моделью, только кости |
| Правка клипа @-FBX (свой, Mixamo, ассет-стор) | ПКМ на @-FBX или на клипе внутри него | Тот же @-FBX |
| Правка клипа, зашитого в FBX модели | ПКМ на клипе внутри FBX модели | Тот же FBX модели |
| Правка .anim | ПКМ на .anim, инспектор, объект с Animator | Тот же .anim (GUID, события, настройки и прочие кривые сохраняются) |
| Новая модель | **Assets ▸ Blender ▸ Create Model…** | Новый FBX в выбранной папке |
| Откат | **Window ▸ Blender Bridge ▸ History** | Файл и .meta из истории |

## Панель Unity в Blender

- **Export to Unity** — пишет только изменившиеся файлы. Рядом меню **Export only…**: модель, активный клип или всё загруженное — принудительно.
- **Лупа** рядом со статусом — проверить, что изменилось, без экспорта.
- **Список проблем** — то, что проверяется перед экспортом. Ошибки блокируют экспорт, но есть **Export anyway**.
- **Pin / Unpin** — закрепить .blend в git или вернуть в кэш.
- **Clips** — клипы модели: свои @-FBX, зашитые дубли, .anim. Клип грузится по клику. Для клипа видны диапазон, Loop и Root motion (для клипов, которыми управляет Blender) и **Simplify keys**.

## Как живут рабочие .blend

- `ArtSource/Cache/…` — рабочие копии, вне git. Удаляются сами, если синхронизированы и не открывались 14 дней. Файлы с неэкспортированными правками не удаляются никогда.
- `ArtSource/Pinned/…` — закреплённые файлы, в git через LFS. Закрепляй, когда в .blend есть то, чего нет в FBX: живые модификаторы, контрол-риг, хай-поли, исходные ключи анимации.
- Если FBX изменился снаружи (git pull, откат), при открытии будет свежий импорт; неэкспортированные правки можно сохранить копией.
- `ArtSource/links.json` (в git) помнит закрепления и какой модели принадлежит клип.

## Соглашения об именах

- **LOD**: `Имя_LOD0`, `Имя_LOD1`… — LODGroup Unity создаёт сама.
- **Коллайдеры**: `Имя_COL` → MeshCollider без рендерера, `Имя_COLC` → выпуклый, несколько — `Имя_COL_1`, `Имя_COL_2`. Суффикс меняется в Project Settings, правило отключается там же.
- **Клипы**: новый клип называется именем экшена и пишется в `Модель@Клип.fbx`.
- **Контрол-риг** держи отдельной арматурой: экспортируется только исходный скелет модели с запечёнными констрейнтами.

## Что проверяется

Перед экспортом (Blender): переименованные или удалённые кости (ошибка), суффиксы `.001` (ошибка), пропавший целевой файл (ошибка), переименованные объекты и слоты материалов, отрицательный масштаб, больше 4 весов на вершину, пропуски в цепочке LOD, shape keys с модификаторами, сторонний файл.

После импорта (Unity): GUID, file ID всех частей модели, положение каждой кости в покое, нетронутые клипы, настройки импорта. Любая ошибка сравнения предлагает откат.

## Материалы

Имена материалов в Blender — это имена слотов в Unity. Unity-материалы инструмент не меняет. Для нового слота ищется .mat с таким же именем (ближе к модели — приоритетнее), иначе копируется шаблонный материал из Project Settings в `Materials/` рядом с моделью.

## Ограничения v1

- Меши вне FBX (.asset, ProBuilder) — в v1.1.
- Дубль, который анимирует несколько скелетов или анимированные вспомогательные объекты (например, пакеты 3ds Max Biped, где в одном файле лежат Biped и UE-скелет), записать нельзя: экспорт остановится с ошибкой «Takes also animate other objects…», файл не будет испорчен.
- Зеркальные концевые кости с отрицательным масштабом (Nub-кости 3ds Max) сохраняют положение, но записываются без зеркала. Об этом будет предупреждение.
- Анимация shape keys сохраняется для файлов с одним дублем.
- Humanoid-клипы .anim правятся через мышцы аватара: кости вне маппинга аватара не правятся.
- Отчёт об импорте прямо в Blender и события анимации из маркеров — в следующих версиях.

## Что проверено на реальном проекте

Цикл FBX → Blender → FBX без правок прогнан на 13 моделях проекта Hokage (Blender 5.2.3 LTS): статика (BigHouse_1, Katana1, Bike), персонажи Mixamo и свои (Rin, Goku, Guts, Liora, Yumi), Dog1 с шестью зашитыми клипами, Archer из ассет-стора с колчаном на кости. Все проходят: нетронутое не меняется, повторные циклы не дают дрейфа, экспорт без правок ничего не пишет.

## Самотест

- **Assets ▸ Blender ▸ Run Self-Test** — цикл FBX → Blender → FBX в фоновом Blender на синтетических файлах и на выделенных FBX. Отчёт в консоли и в Window ▸ Blender Bridge ▸ Cache.
- **Assets ▸ Blender ▸ Run End-to-End Test** — полный путь через Unity на копиях выделенных ассетов: правка вершины, перезапись дублей, новый клип, правка .anim (выдели .anim вместе с моделью). Копии создаются в `Assets/BlenderBridgeSelfTest` и удаляются после теста. Итог — в консоли и в `Library/BlenderBridgeSelfTest/e2e.txt`.

## Самотест из командной строки

Тот же цикл без Unity:

```
<путь к Blender> -b --factory-startup \
  --python "<путь к пакету>/Tests~/blender/phase0.py" -- \
  --ub-out /tmp/ub_phase0 --ub-fbx-dir "<папка с твоими FBX>" --ub-cycles 3
```

Итог — `report.txt` и `report.json` в папке `--ub-out`. `PASS` — первый цикл совпал с оригиналом в допусках, дальнейшие циклы ничего не сдвигают, экспорт без правок не пишет файлов. `BLOCK` — инструмент остановил бы экспорт и объяснил почему (это правильное поведение для неподдерживаемых файлов).

## Неполадки

- **Blender не найден** — Preferences ▸ Blender Bridge ▸ Browse (на macOS можно выбрать Blender.app).
- **Ничего не импортировалось** — Window ▸ Blender Bridge ▸ Cache ▸ Process pending exports now.
- **«Already open in Blender»** — модель уже открыта в другом окне Blender; второе окно может перезаписать работу первого.
- **Ошибка сравнения после импорта** — Window ▸ Blender Bridge ▸ History ▸ Restore.
